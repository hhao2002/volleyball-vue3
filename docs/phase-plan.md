## 2. 需求决策与待确认项

以下为在实现过程中对模糊点的处理方式。如与预期不一致，可在下一阶段调整，均为局部改动。

1. **计分放在后端**（对应 AGENTS.md「是否要出于安全考虑，从后端来计分」）
   - 采用后端计分。前端只发送得分事件，后端校验比赛状态、队伍/球员归属、操作者是否为创建者。
   - 好处：无法通过浏览器篡改比分；实时推送与结果公告天然一致。
2. **出界得分的归属**
   - 计分台的「出界得分」按钮位于得分方一侧，表示该分来自对方击球出界，因此只给该队加分，不记录球员。
   - 若希望改为一侧记录“本队击球出界、对方得分”，只需调整前端按钮位置与后端 `type` 解释。
3. **SVP 的兜底**
   - 负队按同样的优先级选 SVP；若负队无人得分，仍从该队阵容中产生 SVP（各项统计为 0）。
   - 这样每场结束的比赛都有 MVP 与 SVP，公告与结果页不会出现空缺。
4. **撤销上一分**
   - 需求未明确要求，但计分场景必需。仅创建者、比赛进行中可用；撤销后后端重放本场得分记录，重算局分与比分。
5. **创建队伍也要求 6 人**
   - 原文只强调“改队伍时队员数量必须为 6 人”，为保持一致，创建与编辑均校验 6 名不重复队员。
6. **趣味赛制**
   - 除常规 15/21/25 分外，创建比赛时可选 5 分、10 分制，便于快速演示与娱乐赛；后端允许 5-50 分。
7. **数据初始化**
   - 提供 H2 `demo` 档（零配置，带种子数据）与 MySQL 脚本；H2 数据每次重启重置。
8. **队伍锁定范围**
   - 队伍参加进行中的比赛时，队伍与队员均不可修改；比赛结束后自动解锁。已结束比赛的历史比分记录不会被队伍改名影响。

## 3. 关键流程

### 计分流程
1. 计分员创建比赛（选择两支满 6 人且不在比赛中的队伍，设置赛制）。
2. 点击开始：比赛状态变为进行中，队伍锁定，生成「比赛开始」公告。
3. 点击球员或「出界得分」：后端记录事件、更新本局比分；达到目标分且领先 2 分则赢下一局。
4. 赢下过半局数：比赛结束，计算 MVP/SVP，生成「比赛结束」公告，解锁队伍。
5. 每次比分变化通过 WebSocket 推送给该场比赛的观众；前端断线会自动重连并定时兜底刷新。

### MVP / SVP 规则
按以下顺序比较，全部相同则取队员 ID 较小者：

1. 个人总得分；
2. 单次最大连续得分；
3. 连续得分（长度 ≥ 2）的发生次数。

出界得分不归属球员，并且会中断球员的连续得分段。
